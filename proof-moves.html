Proof Moves

These are the reusable moves beneath the lectures. Each recipe starts from the everyday problem, names the legal contract, explains why the move works, and names the failure that would make the proof invalid.

How To Use These Recipes

When a page feels compressed, find the proof move it is using. Do not start with the theorem name. Start with the action: move a picture, build a count, translate a rule, add local defects, or model possible states. Then ask what detail makes the action legal.

The course becomes easier when every proof is read as a sequence of obligations. What is the object? What may change? What must survive? What count or comparison is protected? What conclusion follows because the protected evidence cannot be removed?

A recipe is not complete until the failure mode is visible. For each proof move below, try to say the nearby wrong proof: the illegal deformation, the raw count, the graph of the wrong rule, the missing defect, or the dishonest state space. The wrong proof is what shows why the contract matters.

Deform a picture without changing the original question

The first drawing may be too tangled to reason from directly, but a cleaner drawing answers the original problem only if the path to it respects the original rules. The human temptation is to jump to the easier picture; the mathematical move is to prove that every step of the jump was legal. Plain use of this move starts by asking what would remain confusing if the proof skipped the setup and jumped straight to the conclusion.

Steps:

  1. Name the object that is allowed to move and the data attached to it, such as endpoints, boundary order, glued edges, or obstacles.
  2. Name the forbidden moves: passing through, breaking, gluing, moving endpoints, or dropping a boundary.
  3. Move the picture only through legal changes, checking the in-between moments rather than only the final picture.
  4. State the fact that survived the whole motion and say why it still belongs to the original object.
  5. Use the simpler final picture to answer the original question, while naming the conclusion that the motion is strong enough to support.

Why it works: The proof works because each legal step preserves the question. The final picture speaks for the starting picture because the journey to it was honest and the protected feature can be carried back. This is why the in-between motion is part of the proof, not an animation after the proof has already happened. This makes the proof readable in plain words: the page changes something only after saying why the change still answers the starting question.

Failure mode: The usual failure is simplifying first and justifying later. If endpoints move, a path crosses an obstacle, or a gluing rule changes before the motion is checked, the proof may have solved a different problem. The error can be subtle because the final picture may look clearer while no longer carrying the original boundary data. This failure matters because the wrong proof can look smoother than the right one while quietly answering a different question.

Course example: The disk path puzzle uses deformation to show that endpoint order and no-crossing rules can force an obstruction. The cleaner drawing matters only because those boundary data stayed fixed during the motion. The same habit reappears when knots, strips, or glued edges are redrawn: the route to the simpler picture has to preserve the object. Read the example as a test case for the method, not as a stand-in for every problem in the family.

Family: deformation-family

Build a count that survives legal redrawings by cancellation

The visible number of pieces, crossings, or defects can change when the picture is cleaned up, so the proof needs a count designed to ignore harmless changes. The first count the eye sees is often too fragile; the useful count is built around the local events that threaten it. In everyday terms, this move exists because the first view of the problem is too noisy, too local, too hidden, or too fragile to trust by itself.

Steps:

  1. Decide which local events matter and which visible events are only artifacts of one drawing.
  2. Watch how those events can appear or disappear under legal motion.
  3. Choose an account where harmless changes cancel, such as an alternating count, parity, or a signed total.
  4. Check the account on a simple version of the object and explain why the simplification did not change the object being counted.
  5. Use the protected total to force existence or impossibility, while stating what the count does not classify or locate.

Why it works: A protected count is designed around its allowed changes. Euler characteristic, parity, intersection number, and index all work because local bookkeeping changes either cancel, arrive in pairs, or preserve a signed total. The point is not that numbers are impressive; the point is that the chosen number was built to survive exactly the redraws the problem permits. A reader can trust the move only when the surviving fact is named before the payoff, because that fact is what carries the conclusion.

Failure mode: The raw count is often the wrong count. If the proof does not explain what legal event threatens the number and why the chosen account survives it, the number is only a measurement of one drawing. The page must show the repair: alternating entries, pair parity, or signs that make harmless local changes contribute no net evidence. The boundary is part of the method. If the proof cannot say exactly what breaks, it has not explained why the move is valid.

Course example: Signed intersection number counts plus and minus meetings so pairs born during deformation add to zero. Euler characteristic does a similar job for cell refinements by making added pieces cancel in the alternating ledger. Both examples teach the same first-principles point: count only after saying which changes the count was designed to survive. The same pattern can be used in another lecture or outside field only after the new setting rebuilds the same obligations.

Family: counting-family

Translate an invisible rule into a comparable shape

A map or motion law can feel invisible because it is an instruction rather than a drawn object, so the proof first turns the rule into something comparable. The reader needs a visible record of input, output, and self-agreement before an existence theorem or intersection count can speak. The reader can test the move by naming the object first, because the proof family matters only after the carrier of the question is visible.

Steps:

  1. List the input space and output space, and check whether the rule really sends points back into the space the conclusion needs.
  2. Draw or describe the graph that records input and output together, so the rule becomes a geometric object rather than only a formula.
  3. Identify the comparison object, such as the diagonal of self-agreement.
  4. Turn the desired conclusion into a meeting or avoidance question and state why that meeting means the original rule has the desired property.
  5. Apply the earlier count, obstruction, or fixed-point idea only after the graph and comparison object still represent the original problem.

Why it works: The proof works because the rule becomes an object that can be moved, compared, and counted. A fixed point is no longer hidden inside notation; it is a meeting with the diagonal inside the product space where input and output are recorded together. The translation earns trust only when every graph point still means one input and its actual output. The same habit can travel outside topology when another field rebuilds the object, allowed change, evidence, and limit in its own material.

Failure mode: The translation fails if the graph no longer represents the original rule, if outputs land in the wrong space, or if the diagonal no longer represents the desired self-agreement. Then the drawing may still contain an intersection, but that intersection answers a different question from the one the map asked. Outside topology, the same warning applies when a model, drawing, count, or state space resembles the course example but drops the needed condition.

Course example: Fixed-point lectures turn f(x) = x into the graph of f meeting the diagonal. The graph records what the rule does, the diagonal records self-agreement, and their intersection is the fixed point claim. Brouwer-style reasoning enters only after the graph and diagonal still represent the same space and the same rule. The example matters because it shows the object, the allowed action, the protected evidence, and the exact size of the payoff in one place.

Family: motion-family

Read local defects as evidence about the whole surface

A vector field may have several local failures, and each one can look adjustable in isolation, but the surface may constrain their total account. The hard part is not spotting one bad point; it is entering every isolated defect into the same surface ledger before drawing a global conclusion. In everyday terms, this move exists because the first view of the problem is too noisy, too local, too hidden, or too fragile to trust by itself.

Steps:

  1. Clean the field so the defects are isolated and the surrounding arrows can be read one defect at a time.
  2. Walk around each defect with a small loop that contains that defect and no other defect.
  3. Record how the nearby arrows turn, including the sign of that local turning.
  4. Add the signed local indices over the complete list of defects on the same surface.
  5. Compare the total with the surface's Euler characteristic and state the conclusion as a constraint on defects, not as a solved motion path.

Why it works: The proof works because isolated local defects can move, split, or cancel in controlled ways, but their signed total is tied to the surface that carries the field. The whole surface limits what the local arrow failures can add up to. This turns a local motion problem into a bookkeeping problem over the complete carrier. A reader can trust the move only when the surviving fact is named before the payoff, because that fact is what carries the conclusion.

Failure mode: The theorem is misread when one equilibrium is treated as the whole story, when one defect is omitted, or when the theorem is taken to solve trajectories. Poincare-Hopf is about the total over the complete surface. A single defect can illustrate the idea, but it cannot replace the complete defect list. The boundary is part of the method. If the proof cannot say exactly what breaks, it has not explained why the move is valid.

Course example: The hairy-ball idea is the plain case: a sphere cannot carry a continuous nonzero tangent arrow field everywhere. The reason is not a single bad point; it is the surface-wide defect total required by the sphere. The recipe asks the reader to add every local index before claiming the whole-surface constraint. The same pattern can be used in another lecture or outside field only after the new setting rebuilds the same obligations.

Family: surface-family

Model physical motion as a space of possible states

A physical setup has too many details to track directly over time, so the proof must first decide what counts as one complete allowed state. The model is the mathematical object: if it forgets a real freedom or permits an impossible state, the later theorem speaks about the wrong world. The reader can test the move by naming the object first, because the proof family matters only after the carrier of the question is visible.

Steps:

  1. Say what information describes one complete state, including positions, angles, contacts, or choices the question cares about.
  2. Treat every possible state as a point in a new space, but only after the state description is complete enough for the problem.
  3. Remove forbidden states or mark boundary restrictions such as collisions, blocked positions, or impossible choices.
  4. Translate motion into paths or rules on that state space, checking that every modeled path is a real gradual motion.
  5. Use holes, barriers, fixed points, or indices to constrain the original system, while stating the limit of what the model proves.

Why it works: The proof works only if the state space carries the real freedoms and real exclusions of the physical problem. Topology then reasons about the shape of possibility: paths, holes, walls, separated regions, and forced self-agreement. The equations can be postponed because the space already records which motions are even possible. The same habit can travel outside topology when another field rebuilds the object, allowed change, evidence, and limit in its own material.

Failure mode: A careless state space can prove a true theorem about the wrong model. If a freedom is omitted or a forbidden state remains, the physical conclusion is only as good as the mistaken translation. The failure is especially dangerous because the theorem may be used correctly after the modeling step has already broken faith with the system. Outside topology, the same warning applies when a model, drawing, count, or state space resembles the course example but drops the needed condition.

Course example: The late applications use state spaces and protected obstructions to reason about motion without solving every trajectory. The useful claim is about allowed routes or forced states in the model, not every detail of the physical motion. A good explanation names one complete state, the forbidden states, and the reason paths in the model match real motion. The example matters because it shows the object, the allowed action, the protected evidence, and the exact size of the payoff in one place.

Family: motion-family

Audit Question

After reading any proof in the course, ask which recipe was used and where the proof paid its debt. A deformation proof pays its debt by naming legal motion. A counting proof pays its debt by explaining cancellation. A fixed-point proof pays its debt by translating the rule into a graph-and-diagonal meeting. A dynamics proof pays its debt by showing why local defects can be added over the whole surface.

If the page gives a conclusion before paying that debt, repair it by inserting the missing sentence. The repair should name the object, allowed move, protected evidence, and limit of the conclusion in ordinary language.
